2. Starting point

From scratch, not a fork. We wrote the extension, the MCP server, the retrieval and the review layer ourselves. The only dependencies are libraries: @truefoundry/trueforge-sdk, @modelcontextprotocol/sdk, diff (jsdiff) and zod. The extension never calls a model provider itself. Every model call goes through TrueForge.

How it talks to TrueForge. On startup the extension does two things:

  • It registers its MCP server as the connector forgelens-editor.
  • It syncs two agent definitions from agents/ into the TrueForge registry: forgelens-agent for agent mode and forgelens-inline for inline edit (no tools).

Each request becomes a TrueForge session. We stream its turn events into the editor (model.message.delta, tool.response, thread.*, turn.done), and the panel links to the live session page.

Editor capabilities as MCP tools: the read tools repo_map, search_code, find_symbol, read_file and list_files, and the write tools propose_edit, propose_new_file and run_command. read_file must state a reason, so every file the agent reads appears in the ledger with its why.

Harness featureWhy we use it
require_approval_for_tools on all writes and commandsTrueForge pauses the turn, and the editor shows per-hunk review. The user's decision goes back as user.tool_approval (allow, or deny with a reason the model reads). The harness, not our code, guarantees nothing is written unseen.
dynamic_sub_agentsThe agent's first step delegates read-only exploration to an explorer sub-agent. Only its summary returns, so the main thread's context stays small. The sub-agent shows as its own thread in the panel and in the session.
Deferred tool loading (preload:false)Only the six tools every run needs are preloaded. run_command and list_files are fetched on demand, which saves prompt tokens on every turn.
Compaction (60k tokens) and large_tool_responseLong runs and large test logs can't overflow the model's window, which matters on small free-tier models.
sessions.update, cancel, iteration_limitFallback swaps the model inside the same session, so history is kept. Stop/Esc ends the turn immediately. A runaway loop has a hard ceiling.

Diff safety does not rely on trusting the model. The MCP write tool writes only if three things hold:

  • An accepted-hunk decision exists for that exact call.
  • The file is unchanged since the review.
  • The write contains only the accepted hunks, applied as one atomic edit per file.

Every write is checkpointed, which gives Undo last and Revert run.

Before review, three guards run:

  • old_text must match exactly once, which blocks edits to code that does not exist.
  • Edited Python must still parse.
  • Imports of names that are not in the index are flagged.

Security:

  • A workspace jail blocks .. and symlink escapes, and makes .git, .env and key files unreadable.
  • Secrets are redacted from tool output.
  • Commands come from an allowlist and run without a shell.
  • The MCP endpoint is bound to localhost and needs a bearer token. TrueForge may reach only 127.0.0.1.

4. How context is selected

Index. When the workspace opens, we split every file into symbol-sized chunks: functions and classes with their decorators and qualified names, and documentation sections by heading. A file watcher keeps the index current. Flask 3.1.3 gives 211 files and 1,975 chunks in about 180 ms.

Per request we build a pack under a token budget (default 6,000 tokens, set with forgelens.contextBudgetTokens):

  1. @file and @symbol mentions.
  2. The top BM25 chunks. Path priors down-weight changelogs and tutorials.
  3. Companion expansion for each top source file: its test file (src/pkg/X.py → tests/test_X.py) and the docs page that covers it (docs/X.rst). Changes rarely live in one file.
  4. The remaining chunks by score, at most 3 per file, dropping anything below 25% of the top score.
  5. Chunks that miss the budget are passed as pointers (path, lines and why) that the agent can read_file.
  6. A compact repo map of relevant symbols, with its own budget.

It is visible. The panel's Context ledger lists every snippet with its tokens, its source (mention, retrieval, companion, pointer or agent read) and its reason, plus a budget bar. Real ledgers:

Switching models. Set forgelens.models in VS Code settings. The first entry is the primary model and the rest are fallbacks, in order. No code changes are needed, and any TrueForge provider works, including local models behind an OpenAI-compatible endpoint.

Resilience:

  • Network, 5xx and 429 errors retry with exponential backoff.
  • Auth, unknown-model and daily-quota errors skip retries.
  • After retries, ForgeLens falls back to the next model in the same session.
  • All of this is async, so the editor never blocks.

Settings: the agent runs at temperature 0.2 with 8k max output, and inline edit at temperature 0 with 4k. Total Gemini spend for development, testing and recording (billing account, 1–20 Nov 2026) was ₹108.14 (about US$1.25). Groq was used on its free tier.

7. Tools used

  • Runtime: TrueForge (local mode) and the VS Code Extension API.
  • Libraries: TrueForge SDK, MCP TypeScript SDK, jsdiff, zod.
  • Build and test: TypeScript, esbuild and node:test, with 11 unit tests covering the security, retrieval, hunk and guard logic.
  • Models: Google Gemini and Groq.
  • Test target: Flask 3.1.3 with pytest.
  • AI coding assistant: Claude Code, used to write and review code. The team made the design decisions and did the testing.

8. Known limitations and what we would do with another month

  • Lexical retrieval. BM25, symbols and companions can miss synonyms that share no words with the request. Pointers and the agent's own search reduce this. Next month: add a small local embedding index and rerank over BM25 candidates.
  • Python-first. The symbol parser and syntax guard cover Python only, and other languages fall back to line windows. Next month: use tree-sitter for TypeScript, Go and Java.
  • Undo. Plain Ctrl+Z after an inline accept changes the buffer but does not save it. Undo last reverts and saves.
  • Model-dependent behaviour. The sub-agent step is an instruction, so a weak model may skip it. Free-tier quotas are too small for repeated agent runs. Next month: use a TrueForge skill for the explore → plan → edit → test loop, and an eval harness that runs Tasks A–C against several models in CI.
  • Platform. We tested on Windows 11 only. The code paths are cross-platform, but macOS and Linux are unverified.
