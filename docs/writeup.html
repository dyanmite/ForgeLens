2. Starting point

From scratch, not a fork. We wrote the extension, the MCP server, the retrieval and the review layer ourselves. The only dependencies are libraries: @truefoundry/trueforge-sdk (talks to TrueForge), @modelcontextprotocol/sdk (serves the editor tools over MCP), diff (line diffs for hunks) and zod (tool schemas). The extension never calls a model provider itself. Every model call goes through TrueForge.

3. Architecture on TrueForge

  VS Code · ForgeLens extension                          TrueForge (local mode, :8790)
  ─────────────────────────────                          ─────────────────────────────
  Agent panel  /  Inline edit (hunks + CodeLens)

    propose_edit* · propose_new_file* · run_command*      (* need approval)
        │
  RepoIndex (symbols, BM25) · ApprovalBook (per hunk) · guards · checkpoints
  • TrueForge runs the agent loop. On startup the extension registers its MCP server as the TrueForge connector forgelens-editor and syncs two agent definitions from agents/ into the registry: forgelens-agent (agent mode) and forgelens-inline (inline edit, no tools). Each request is a TrueForge session. We stream its turn events (model.message.delta, tool.response, thread.*, turn.done) into the panel, and the panel links to the live session at /sessions/<id>.
  • TrueForge features we use:
    • require_approval_for_tools on every write and command tool. TrueForge pauses the turn (tool.approval_required), we show per-hunk review, and we resume with a user.tool_approval allow or deny that includes a reason.
    • Deferred tool loading (preload:false plus a preload list).
    • dynamic_sub_agents for read-only exploration.
    • Context compaction at 60k input tokens, with large-tool-response handling.
    • iteration_limit as a hard stop.
    • sessions.update to swap the model in the same session when we fall back, so history is kept.
    • cancel for Stop/Esc.
  • Diff safety does not rely on trusting the model. TrueForge approval is the first gate. The MCP write tool is the second: it writes only if an accepted-hunk decision exists for that exact call (hashed arguments), and only if the file has not changed since the review. It writes only the accepted hunks, as one atomic workspace edit per file, preserving CRLF. Each write is checkpointed, so we support Undo last, Revert run and plain Ctrl+Z. A cancelled run cannot leave half an edit, because nothing is written until a whole file's accepted hunks are applied.
  • Guards before review:
    • old_text must match exactly once. This blocks edits to code that does not exist, and the model gets the reason back.
    • Edited Python must still parse (ast).
    • Imports of names that are not in the index are flagged.
  • Security:
    • Workspace jail: no .., absolute or symlink escapes. .git, virtualenvs, .env*, keys and credential files are unreadable.
    • Secret-shaped strings are redacted from every tool result.
    • Commands: allowlist only (pytest, flask, read-only git/pip), spawned with no shell, stripped environment, timeout and output cap.
    • MCP endpoint: bound to 127.0.0.1, random bearer token per session, Host and Origin checks. TrueForge is started with OUTBOUND_URL_ALLOWED_HOSTS=["127.0.0.1"], which allows exactly our endpoint and nothing else on the private network.
    • 11 unit tests cover these checks.

4. How context is selected

Index. When the workspace opens we index it: Flask 3.1.3 has 211 files and 1,975 chunks, indexed in about 180 ms. A file watcher keeps the index current. Chunks are symbol-sized: Python functions and classes with decorators and qualified names, and documentation sections by heading.

The pack is built for every request under a token budget (default 6,000 tokens, configurable). It is assembled in this order:

  1. @file and @symbol mentions.
  2. The top BM25 chunks. Path priors down-weight changelogs and tutorials.
  3. Companion expansion: for a source file, add its test file (src/flask/cli.py → tests/test_cli.py) and the docs page it belongs with (docs/cli.rst).
  4. The rest by score, at most 3 chunks per file, dropping anything below 25% of the top score.
  5. Items that miss the budget are passed as pointers (path, lines and why) so the agent can read_file them.
  6. A compact repo map of the most relevant symbols, with its own budget.

It is visible. The panel's Context ledger shows every snippet with its tokens, its source (mention, retrieval, companion, pointer) and its reason, plus a budget bar. Every file the agent later reads is added to the ledger with the reason the agent gave; read_file requires one. Actual ledgers:

groq/openai-gpt-oss-120bFallback 2Custom OpenAI-compatible provider. The free tier's tokens-per-minute limit suits inline edits only.
unreachable/broken-modelTask C onlyCustom provider at 127.0.0.1:59999, a closed port that gives a real ECONNREFUSED.
  • Resilience policy:
    • Transient errors (network, 5xx, 429) retry with exponential backoff (0.8s, 1.6s, longer for 429).
    • Auth, missing-model and daily-quota errors skip the retries.
    • Then ForgeLens falls back to the next model in the same TrueForge session. If the turn had already made progress, it continues instead of restarting.
    • Everything is async, so the editor stays responsive.
  • Settings: agent temperature 0.2 and 8k max output; inline temperature 0 and 4k. Models are switched with the forgelens.models setting with no code change. Any provider TrueForge supports works, including local models.
  • Measured: in Task C the run went from failure, through retry and fallback, to a finished edit in about 4 s, with git status clean throughout. [Task B tokens / cost from the TrueForge session]

7. Tools used

  • Runtime: TrueForge (local mode), VS Code Extension API.
  • Libraries: TrueForge SDK, MCP TypeScript SDK, jsdiff, zod.
  • Build and test: TypeScript, esbuild, node:test.
  • Models: Google Gemini, Groq.
  • Test target: Flask 3.1.3 with pytest 9.0.2.
  • AI assistance: Claude Code was used during development to write and review code. All design decisions and testing were the team's.

8. Known limitations

  • Retrieval is lexical (BM25 plus symbols and companions), not embeddings, so synonyms with no shared words can be missed. Pointers and the agent's own search_code reduce the risk.
  • Language support: the symbol parser and syntax guard are Python-specific. Other languages are indexed in fixed line windows, with no symbols and no parse check.
  • Undo: plain Ctrl+Z after an inline accept changes the buffer but does not save it. Use Undo last, which reverts and saves.
  • Free-tier limits: Gemini Flash's free daily quota is too small for a full agent run. We rely on fallback, and on paid quota for the recorded Task B.
  • Sub-agents: whether a sub-agent is used is the model's decision. It is enabled but not forced.
  • Platform: tested on Windows 11. macOS and Linux should work, since paths and spawning are cross-platform, but we did not run them.
